# F0/F1 第一批实施记录

日期：2026-09-16。基于 `4399d70`，对应 [v6 产品方案](./融合陪伴与循证问答产品方案-v6.md)与 [v6 技术架构](./融合陪伴与循证问答技术架构-v6.md)的受限增量，不代表 F0/F1 全部完成。

## 本轮范围

- `response_policy.py`：所有新回答进入统一的文本、禁止模式与引用格式检查。内部固定身份/安全模板不按禁止词误拦，但不向模型或客户端提供绕过开关。
- 生成未配置、超时、失败或无正文时，不再返回原始知识分块；有检索结果但未生成答案与没有检索依据采用不同状态。
- 引用必须使用本次结果中存在的 `[1]` 至 `[3]`；知识生成未标引用、越界编号、合并/范围引用会被拦截。只返回实际被引用的片段，保持原编号，不把未引用的 top-k 显示成答案依据。
- `conversation_state.py`：识别完整、明确的暂停/恢复建议子句，记录 `open/deferred` 和服务端 request_id 来源。普通回复不改变来源；不把模型输出写成健康画像。
- 会话存储可通过 `with_state=True` 给回调传入独立状态，状态与本轮回复原子保存，不混入最近 3 轮原文。旧记录从空状态开始，旧回调接口保持兼容。
- 暂停建议期间使用不含解决方案的固定倾听回复；明确知识追问是单轮例外，不永久清除暂停偏好。用户明确恢复建议才更新为 open。
- 当前明确急症、危机、医疗边界先于偏好执行；可见近期风险不会因暂停建议或结束请求而转为普通倾听。
- 明确结束时不追加问题；修正“推荐怎么休息”被当品牌咨询，以及离线休息文案暗示闭眼照护的问题。

## 响应与存储

请求仍为 `query / request_id / revision`。客户端 `history / state / conversation_state` 均不接受。

新增响应字段：

| 字段 | 含义 |
|---|---|
| `conversation_state.version` | 当前为 1，服务端结构版本 |
| `conversation_state.advice_preference` | mode 与 source_request_id；默认会话内，非长期记忆 |
| `knowledge_status` | not_requested、deferred、insufficient_evidence、generation_unavailable、referenced、prohibited 或 output_blocked |
| `execution.validator` | fixed、passed 或具体机械检查失败原因 |
| `citations[].citation_number` | 原始引用编号，筛选后不重新编号 |

`referenced` 只表示答案通过基础引用检查，不代表已审核或事实被证据充分支持。`passed` 不是医学安全认证。状态保留现有固定 24h TTL、请求触发清理和删除规则，不新增永久存储。

## 验证方法

```bash
python3 -m unittest -v test_app test_conversation_store test_session_api test_fusion
node --check static/app.js
```

`test_fusion.py` 是确定性程序回归，不是真实模型质量评测。覆盖偏好识别反例、当前风险优先、混合问题缺证据、引用映射、生成故障、跨历史窗口/重启/删除。测试证据是合成占位内容，不是已审核医学资料。

## 尚未完成与已知限制

- 未实现审核知识卡、逐 claim 语义支持检查、版本/人群条件验证。配置真实模型后仍是基于已导入内容的尽力约束回答，不宣称严格事实闭域。
- 禁止词是机械规则，有误报和漏报；引用正确不等于结论正确。语义上越界但未命中规则的陈述仍可能通过。
- 偏好识别只覆盖明确子句，不是完整中文意图理解；当前为会话级暂停，不区分多主题范围，也没有记录所有被拒绝的具体建议。暂停期间固定话术的自然度尚需评测。
- 风险检查保留既有词表与有限原文历史，没有实现跨窗口风险状态、否定/主体/时态建模和地区化资源治理。
- 未实现多子问题分解与子问题级医疗边界；高风险请求仍可能导致整轮固定回复。
- 未建立 v6 约 60 段真实模型多轮评测集，未部署 AstrBot 做对照，未完成专业人员评审；单测数量不能替代这些工作。
- 不新增账号、FastAPI、PostgreSQL、LangGraph、向量数据库或实时语音服务。仍仅适用于本地单进程 Demo。

下一步应完成审核内容发布与最小知识卡闭环，并建立融合场景的真实模型离线评测，再决定是否引入更复杂检索或替换底座。
