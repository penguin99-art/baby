# M0/M1 第一批实施记录

日期：2026-09-16。对应 v5 的基线与会话可靠性工作，不代表 M1 全部完成。

## 已实现

- `conversation_store.py`：SQLite 持久会话、凭证摘要、固定 24 小时 TTL、请求触发过期清理、显式删除。
- 同一会话串行执行、request_id 幂等和 revision 冲突检查；生成期间不持有数据库写事务，提交时再次检查会话状态。
- 服务端提供最近 3 轮用户/助手消息；前端不再提供任意历史或 route。页面刷新恢复历史。
- `conversation_plan.py`：dataclass 契约验证 JSON 类型、枚举、长度和额外字段；模型错误不再通过截取花括号或字符串强转掩盖。
- `execution` 记录规划与生成结果、固定能力、降级、输出阻断。危险输出被阻断后不再回退原始知识片段。
- 前端发送锁、重复重试 ID、冲突同步、保留失败草稿、删除会话；只显示真实运行模式。
- 浏览器语音改为转写确认后发送，自动朗读默认关闭，手动播放独立，实际结束事件更新按钮。
- Host/Origin 检查、POST 自定义头要求、HttpOnly/SameSite Cookie。本地保护而非生产账号系统。

## 验证范围

自动测试涵盖单轮既有行为、会话隔离、重启恢复、幂等、并发重复、冲突、删除、过期、失败不写入、计划校验、输出阻断和 API 契约。浏览器验证刷新恢复、连续短回复和移动端布局。

本轮运行 48 条自动测试全部通过；浏览器验证了 390px 移动布局、桌面布局、删除会话后刷新仍为空。独立代码审查完成，无本地 Demo 范围内的阻塞项。

测试是程序正确性证据，不是医学正确性或陪伴质量证据。本轮没有使用真实供应商测评生成质量，语音没有验证真实麦克风/扬声器硬件。

## 尚未实现

- FastAPI / Pydantic 迁移：为缩小改动，本轮仍使用 stdlib HTTPServer 与 dataclass。
- 状态摘要、已拒绝建议、跨会话偏好和风险趋势：当前仍提供有界原文历史，不能宣称结构化长期记忆。
- PostgreSQL/pgvector、BM25、reranker、知识审核快照、逐 claim 事实校验。
- 专业内容仍受现有分类与提示约束，尚不具备生成式事实零越界保证。
- 多进程分布式锁、账号鉴权、HTTPS、Secret Manager、生产限流、真实人工接收。
- 同一会话生成期间，其他标签页的读取或删除会等待本轮完成；当前串行锁可能使等待持续至模型超时。需要多标签实时体验时再引入可取消任务和异步会话读取。
- 实时语音服务、后台定时删除、数据加密、专家多轮盲评和性能 SLO。

## 升级注意

这是 `/api/ask` 的契约变更。旧前端须刷新；客户端不能继续传 history。历史会话是本地健康/情绪数据，请勿公开暴露端口或将 SQLite 文件提交到 Git。

会话删除不保证已导出的副本、备份或供应商日志同步删除；生产部署需要独立保留与删除政策。Token 的哈希不是对会话内容的加密。

本轮不替换现有运行服务的内存 API Key，不将旧密钥写入文件。新进程未配置 API 时会明确显示“本地降级”。
