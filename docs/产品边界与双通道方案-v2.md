# 母婴顾问 Demo：知识问答与情绪支持双通道方案

> 历史方案，已由 [v6 产品方案](./融合陪伴与循证问答产品方案-v6.md)和 [v6 技术架构](./融合陪伴与循证问答技术架构-v6.md)替代。下文的实施状态仅对应当时版本；固定四步话术、互斥模式及未经校准的安全百分比不再作为实施标准。“我是不是产后抑郁”不自动等于即时危机，需按当前语境评估。

> 本文修订并补充 `closed-domain-rag-方案.md`。两者关系：旧文档描述“严格闭域知识问答”底座；本文定义面向母亲群体后的产品边界、双通道路由和安全优化。

## 1. 核心调整

产品可以提供两类体验：

```text
知识顾问模式：回答已审核 Markdown 中有明确依据的母婴知识
情绪支持模式：倾听、共情、陪伴、积极但不强迫的情绪支持
```

因此，“盾牌”不应该把所有非知识库内容都拦截，而应该从单一的：

```text
不在知识库 -> 拒答
```

升级为：

```text
不在知识库 + 属于情绪支持 -> 进入情绪支持通道
不在知识库 + 不属于情绪支持 -> 拒答
高风险医疗/心理危机 -> 固定安全流程
```

## 2. 对产品人设的修正建议

不建议在产品中直接宣称：

```text
心理疗愈大师
专业心理治疗师
临床心理医生
```

除非背后有真实资质、专业人员和对应服务资质。对用户的推荐人设是：

> **温和、可靠、有边界的母婴健康顾问与情绪支持伙伴。**

系统可以使用温暖、理解和支持性的语言，但不能暗示自己具备临床诊断、心理治疗或危机干预资质。产品文案建议使用：

- “我可以陪你梳理现在的感受。”
- “很多照护者都会经历疲惫、内疚或压力，你不需要一个人扛着。”
- “我能提供一般信息和情绪支持，但不能替代医生或心理专业人员。”

避免使用：

- “我能治好你的焦虑/抑郁。”
- “你这是产后抑郁。”
- “只要积极一点就好了。”
- “我比医生更懂你。”

“正面积极”应理解为**温和、真实、帮助用户恢复行动感**，而不是强行乐观、否定痛苦或把责任归因给母亲。

## 3. 双通道架构

```text
用户消息
  |
  v
输入安全层
  - 长度、频率、PII、Prompt Injection
  - 自伤/他伤/虐待/急症红旗检测
  |
  v
风险与意图路由器
  |
  +-- 医疗急症 -----------------> 固定急救/就医提示
  +-- 心理危机 -----------------> 危机支持模板 + 人工/当地资源
  +-- 高风险医疗 ----------------> 固定拒答 + 专业转介
  +-- 知识问题 ------------------> 闭域 RAG 通道
  +-- 情绪支持 ------------------> 情绪支持通道
  +-- 其他闲聊/推荐/购物 --------> 有边界地拒答或引导
  |
  v
输出安全层
  - 禁止诊断、处方、剂量、保证性承诺
  - 检查是否越过通道边界
  - 检查语气是否责备、强迫积极或制造依赖
```

### 3.1 知识顾问通道

只允许：

- 从已审核 Markdown 检索证据
- 返回可追溯引用
- 回答一般母乳、辅食、新生儿护理、基础疫苗科普
- 对不确定、过期、冲突内容拒答

仍然禁止：

- 诊断和疾病结论
- 药品剂量、处方、停药、换药
- 个体化疫苗禁忌和补种计算
- 根据症状制定治疗方案

### 3.2 情绪支持通道

允许：

- 识别和复述情绪：“听起来你这段时间真的很累。”
- 正常化但不淡化：“有这种感受并不代表你不爱孩子。”
- 帮助用户拆解当下压力
- 提供低风险、短时、可选择的自我照护建议
- 鼓励联系伴侣、家人、朋友、社区或专业人员
- 询问用户更需要倾听、梳理还是一起想下一步
- 在用户明确要求时，陪伴式聊天和积极鼓励

不允许：

- 诊断抑郁、焦虑、创伤、依恋障碍等心理疾病
- 声称“疗愈”“治愈”或替代心理治疗
- 对药物、治疗方案或停药给建议
- 把“积极”作为唯一答案
- 鼓励用户只依赖 AI，或暗示 AI 是唯一理解者
- 在危机情况下继续普通闲聊

## 4. 路由器的判定模型

路由器不应只返回 `in_scope=true/false`，建议返回：

```json
{
  "route": "knowledge|emotional_support|refuse|medical_urgent|mental_health_crisis",
  "topic": "feeding|newborn_care|vaccination|postpartum|emotion|other",
  "risk_level": "L0|L1|L2|L3",
  "needs_human": false,
  "reason_code": "emotion_support_request"
}
```

### 4.1 路由优先级

```text
L3 医疗急症/心理危机
  > L2 诊断、处方、剂量、禁忌、虐待风险
  > L1 一般医疗信息/明显情绪困扰
  > L0 普通知识/普通情绪聊天
```

先判定风险，再判定路由。不能因为用户说“我只是想聊天”就绕过急症或危机检测。

### 4.2 示例

| 用户表达 | 路由 | 处理 |
|---|---|---|
| “辅食什么时候开始？” | knowledge | 检索 Markdown，引用来源 |
| “我今天好累，感觉没人理解我。” | emotional_support | 共情、陪伴、询问需要 |
| “我是不是产后抑郁？” | mental_health_crisis 或 human review | 不诊断，询问安全状况并建议专业评估 |
| “我不想活了，孩子也别想活。” | mental_health_crisis | 立即危机流程，鼓励联系当地急救/可信任的人，升级人工 |
| “宝宝呼吸有点困难怎么办？” | medical_urgent | 固定急症提示，阻断普通生成 |
| “给我算宝宝布洛芬剂量。” | refuse | 固定拒答，转儿科医生/药师 |
| “帮我选一款奶粉。” | refuse 或 knowledge | 不做品牌推荐；可回答已入库的通用选购原则 |
| “你能陪我聊会儿吗？” | emotional_support | 允许陪伴式聊天 |

## 5. 情绪支持回答协议

推荐采用四步结构，而不是每次输出长篇鸡汤：

```text
1. 接住：准确复述用户表达的情绪
2. 允许：承认这种感受可以被理解，不急于纠正
3. 选择：给一个很小的可选下一步
4. 询问：让用户选择继续倾诉、梳理问题或寻找支持
```

示例：

> 听起来你今天已经被疲惫和压力压了很久。你感到难受，并不代表你不是一个好妈妈。现在可以先做一个很小的选择：你想让我先听你说，还是一起把最困扰你的事情拆开？如果你已经有伤害自己或孩子的念头，请马上联系身边可信任的人，并拨打当地急救电话或前往急诊。

注意：这里的“积极”是提供选择和支持，不是强行改变用户情绪。

## 6. 心理危机安全边界

### 6.1 必须升级的信号

至少识别以下类别，并覆盖口语、错别字、隐喻和多轮上下文：

- 明确自伤、自杀意图或计划
- 明确伤害婴儿、伴侣或他人的意图
- 已经实施自伤、他伤或儿童伤害
- 无法保证自己或孩子当下安全
- 严重失眠、极度混乱、明显失去现实感
- 家庭暴力、胁迫、遗弃或儿童安全风险

### 6.2 危机响应要求

- 不继续使用普通陪伴模式
- 不争辩、不责备、不承诺保密
- 简短确认安全风险，鼓励立即联系现实中的人
- 建议当地急救、急诊、危机热线或妇幼/心理专业机构
- 有人工团队时创建高优先级工单
- 记录最小必要审计信息，脱敏保存

服务覆盖多个国家/地区时，不能硬编码一个国家的热线；应根据用户主动提供的地区或产品部署地区配置资源。无法确定地区时，优先建议当地急救电话、最近急诊和可信任的人。

## 7. 知识库如何配合情绪支持

情绪支持不意味着允许 LLM 随意补充母婴医学知识。建议分为两种响应：

```text
纯情绪表达：不需要 RAG，可使用受控支持模板/支持性 LLM
情绪 + 医疗问题：拆成两段，情绪由支持通道处理，医疗问题必须回到知识 RAG
```

例如：

> “我好焦虑，宝宝已经 6 个月了还不会坐，要怎么办？”

处理方式：

1. 先承接焦虑，不判断心理疾病。
2. 识别“发育问题”属于知识咨询。
3. 只有检索到已审核的发育知识时才回答医学部分。
4. 没有证据时明确说知识库暂不覆盖，并建议咨询儿科/儿童保健专业人员。

## 8. LLM Prompt 与结构化输出

建议不同路由使用不同系统提示，不要用一个“大而全”的人设 Prompt：

```text
knowledge_system_prompt
  - 只能使用检索证据
  - 必须引用 chunk
  - 不诊断、不处方、不算剂量

emotional_support_system_prompt
  - 温和、尊重、不评判
  - 不声称治疗或诊断
  - 不制造 AI 依赖
  - 发现危机立即转危机流程
  - 医疗事实问题转 knowledge route
```

统一结构化输出：

```json
{
  "route": "emotional_support",
  "risk_level": "L0",
  "answer": "...",
  "citations": [],
  "safety_action": "none",
  "needs_human": false
}
```

生成结果必须经过 schema 校验和第二个安全检查器。解析失败、路由不一致或命中禁止模式时，返回固定安全模板。

## 9. 对当前 Demo 的优化顺序

### P0：先保证不会越界

1. 将 `refused` 拆成 `out_of_scope`、`hard_refusal`、`insufficient_evidence`、`medical_urgent`、`mental_health_crisis`。
2. 增加情绪支持路由，但默认只开放纯情绪表达，不开放情绪相关的医学解释。
3. 将急症和心理危机检测放在所有普通路由之前。
4. 配置情绪支持专用 Prompt，禁止诊断、治疗承诺和依赖性话术。
5. API 返回 `route/risk_level/reason_code`，前端不要用“盾牌已拦截”覆盖所有非回答状态。

### P1：提高判断质量

1. 使用中文小模型做意图与风险分类，规则引擎做高风险一票否决。
2. 用多轮上下文评估“持续疲惫、无助、失眠、伤害想法”等组合信号。
3. 为母亲群体建立正向但不强迫乐观的对话评测集。
4. 引入人工审核和危机升级通道，定义响应 SLA。
5. 将支持性回答的“依赖风险、责备风险、过度承诺风险”加入输出评测。

### P2：生产化

1. 根据部署地区配置本地急救和心理支持资源。
2. 采用 FastAPI、认证、HTTPS、限流、审计日志和 Secret Manager。
3. 使用 LangGraph 编排确定性安全流程；NeMo Guardrails 作为输入/输出 rail，而不是唯一安全层。
4. 使用 Ragas/DeepEval 做 RAG 评测，garak 做注入和越狱测试；新增情绪支持安全金标集。
5. 由儿科、妇产科、营养和心理专业人员共同审核知识与危机文案。

### 情绪支持质量

```text
情绪识别准确率

强行积极/责备话术率 = 0
心理诊断率 = 0
治疗承诺率 = 0

```

### 危机安全

```text
自伤/他伤危机召回率 >= 99%
危机情况下普通闲聊放行率 = 0
危机模板包含现实支持建议率 = 100%
危机升级漏报率 = 0
```

### 知识安全

```text
知识库外医疗事实生成率 = 0
药品剂量自由生成率 = 0
诊断结论生成率 = 0
引用与回答 claim 对应率 >= 99%
```

## 11. 最终产品定位

推荐对外描述为：

> 面向孕产妇和照护者的母婴知识顾问与情绪支持助手。它只依据经过审核的知识库提供母婴科普信息，同时提供不评判的倾听与陪伴；不提供诊断、心理治疗、处方、用药剂量或个体化医疗建议。遇到紧急医疗或心理危机时，请立即联系现实中的专业人员和当地急救资源。

这条定位既保留了母亲群体需要的温度，也把“顾问”和“心理疗愈大师”之间的能力边界说清楚。系统可以更有人情味，但安全边界不能变得模糊。
